# 验证码触发、输入框搜索与结果复制设计

## 背景

当前识别链路可以得到 OCR 结果，但字段匹配只覆盖当前文档中的 `input`，并且对无标签、中文页面文字和较远输入框的容错不足。因此会出现“识别成功，但没有找到验证码输入框”。现有右键图片菜单继续保留，但增加更快的图片快捷触发，并让用户在无法自动填充时直接看到可用结果。

## 目标与非目标

目标：

- 按住 `Ctrl` 或 `Command` 点击验证码图片时触发一次显式识别。
- 扩大当前文档内可编辑验证码输入控件的搜索范围和语义匹配能力。
- 只有唯一且足够可信的字段才自动填充；不确定时展示结果并等待用户确认。
- 未找到输入框时展示识别结果，并按用户设置自动复制识别值到剪贴板。
- 右键图片菜单继续工作，并作为没有快捷键或页面事件不便使用时的兜底方案。
- 所有用户可见的扩展文案改为中文。

非目标：

- 本次不做跨域 iframe 的跨文档字段协调。
- 本次不做跨 Shadow DOM 的全页面遍历。
- 不改变 OCR 模型、结果解释规则和自动识别候选阈值。

## 方案

### 1. 输入框候选收集与匹配

保留现有 `ImageDetailSnapshot` 接口边界，扩展快照中的字段收集器：

- 收集当前文档中所有可见、未禁用、未只读、值为空的文本类 `input`，并支持 `textarea`；不纳入密码、文件、按钮、复选框等控件。
- 字段上下文同时读取 `id`、`name`、`placeholder`、`aria-label`、关联 `label`、祖先/相邻文本、所在 `form` 和与验证码图片的几何距离。
- 匹配语义词覆盖中英文验证码表达（如验证码、校验码、验证、captcha、verification、code、security 等）。
- 扩大“同区域/较近”的距离分段，但保留候选排序和唯一性边界；多个分数接近的候选不自动填充。
- 填充逻辑抽取为对文本输入控件的共享实现，继续使用原生 setter 和 `input/change` 事件，防止破坏页面框架状态。

### 2. 触发与兜底

- 内容脚本在捕获阶段监听 `click`。只有事件目标位于可见验证码 `img`，且 `ctrlKey || metaKey` 为真时才处理；调用显式工作流，避免普通点击产生识别。
- 处理快捷键点击时阻止图片默认行为，避免浏览器打开/拖拽图片；不改变普通点击和右键行为。
- 右键菜单继续通过现有后台消息链路定位图片并触发 `context` 工作流，菜单标题改为中文。

### 3. 结果展示与剪贴板

- 工作流结果继续携带 `displayText` 和 `fillValue`。
- `no_field` 状态显示“识别结果：xxx，未找到验证码输入框”等明确中文文案；结果为空时仍显示失败原因。
- 新增可注入的剪贴板写入函数，优先使用 `navigator.clipboard.writeText`，必要时使用页面内兼容回退；写入失败不影响结果展示，并明确提示复制失败。
- 仅在结果为 `no_field` 且复制设置开启时执行自动复制；不对 `no_candidate`、模型失败或权限失败执行复制。

### 4. 配置与消息

- 设置存储增加布尔项 `copyOnNoField`，默认 `true`；读取旧版本设置时自动补默认值，写入时保存新字段，不丢失现有站点白名单。
- 弹窗增加中文复选框“未找到输入框时自动复制识别结果”，读取和保存该全局设置。
- 后台增加获取/更新偏好设置的运行时消息；内容脚本在处理 `no_field` 时读取当前值，保证打开时间较长的页面也能使用最新配置。
- 站点启用、禁用和模型状态消息保持现有协议兼容。

## 错误处理

- 无可识别图片、图片读取失败、权限拒绝、模型不可用等状态继续沿用现有工作流结果，并使用中文状态消息。
- 快捷键点击不满足图片或修饰键条件时静默忽略，避免干扰页面交互。
- 剪贴板 API 不可用、拒绝或写入失败时，仍显示识别结果，并提示“复制失败，请手动复制”。
- 候选字段无法唯一确定时不自动填充，状态条提供识别结果和现有确认填充动作。

## 测试计划

- DOM 快照：无标签输入、中文标签/占位符、较远但同区域输入、`textarea`，以及不合格控件过滤。
- 字段匹配/工作流：唯一候选自动填充、多个候选确认、无候选返回 `no_field` 并保留结果。
- 内容脚本：`Ctrl/Command + 左键`只响应图片，普通点击不触发，右键消息仍能工作；无字段时复制开关开启/关闭及复制失败提示。
- 设置存储与后台路由：旧数据迁移、默认值、读写偏好消息和并发保存。
- 弹窗与状态条：中文文案、复选框状态、识别结果和复制状态展示。

## 验收标准

1. 在验证码图片上按住 `Ctrl`（Windows/Linux）或 `Command`（macOS）左键点击，会触发识别；普通左键不触发。
2. 现有“识别成功但没有找到输入框”的页面，在候选输入框可安全判定时能自动填充；无法唯一判定时不会误填。
3. 没有输入框时，页面显示完整识别结果；复制设置开启时自动复制，关闭时不复制，复制失败有明确提示。
4. 右键菜单仍可触发识别，菜单和弹窗中的用户可见文字为中文。
5. 现有自动识别、模型状态和权限流程的测试保持通过。
