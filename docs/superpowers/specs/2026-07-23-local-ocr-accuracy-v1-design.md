# 本地 OCR 准确率优化第一版设计

日期：2026-07-23

## 目标

在完全本地运行的前提下，为现有 `common_old.onnx` OCR 管线实现第一轮可验证优化。第一版重点解决算术验证码中减号被 CTC blank 吞掉的问题，并建立可以逐步优化的评测口径。

本阶段允许准确率暂时低于产品硬门槛，但不得降低或绕过原有门槛。只有普通三类整串准确率和算术最终填写值准确率均达到 90%，Task 7 及后续页面自动化任务才能恢复。

## 范围

第一版包含：

- 为算术模式增加语法约束 CTC 解码。
- 保留现有贪心解码作为回退路径。
- 解耦生成基准中的运算符、字体、对比度、干扰线和旋转变量。
- 增加按运算符、选择性准确率和覆盖率指标。
- 在同一份新语料上记录优化前后的本地基准结果。
- 更新进度交接文档，记录实际收益和下一轮建议。

第一版不包含：

- 新增远程 OCR、CDN、API、遥测或运行时下载。
- 更换或新增生产 OCR 模型。
- 针对真实网站的自动识别、字段匹配或自动填写。
- 为通过门槛而降低语料难度、忽略大小写或修改正确答案。
- 通用图像二值化、预处理集成或模型训练。

## 现状与依据

当前 200 张生成语料上的 ddddocr 结果为：

- 普通三类整串准确率：70.67%。
- 算术最终填写值准确率：52%。
- digits：100%。
- letters：56%。
- alphanumeric：56%。
- arithmetic source：50%。

错误分析表明：

- letters 的 22 个错误中有 18 个仅为大小写错误。
- alphanumeric 的 22 个错误中有 19 个仅为大小写错误。
- 加法 13/13、乘法 12/12，减法 0/13、除法 0/12。
- 减号在关键 timestep 的 logit 接近 blank，完整序列约束有恢复空间。
- 除号通常被模型识别成减号，单靠算术语法不能可靠区分，留待后续专用运算符分类器解决。
- 固定阈值二值化显著降低普通验证码准确率，不进入第一版。
- 较大的 `common.onnx` 在匹配 beta 字符表和输入范围后仍低于现有模型，不进入第一版。

## 方案选择

采用解码器优先方案。

该方案复用现有 ONNX 推理结果，不增加第二次模型推理，不增加生产包资源，也不改变普通验证码路径。与预处理集成相比，它的延迟和影响面更小；与训练专用模型相比，它可以先验证现有 logits 中尚未利用的序列信息。

## 架构

### 算术语法解码器

新增 `src/ocr/arithmetic-ctc-decoder.ts`，提供独立的纯函数：

```ts
export function decodeArithmeticCtc(
  logits: Float32Array,
  dims: readonly number[],
  charset: readonly string[],
): { text: string; confidence: number } | null;
```

解码器使用 CTC prefix beam search，并将候选限制在以下语法：

```text
digits operator digits optionalSuffix
digits        := [0-9]+
operator      := + | - | * | / | x | X | × | ÷
optionalSuffix := empty | = | ?
```

设计约束：

- beam width 固定为 24，避免输入导致无界内存增长。
- 最大输出长度复用 `MAX_OCR_TEXT_LENGTH`。
- 所有概率计算使用 log-space，避免长序列下溢。
- CTC blank、连续重复字符和 blank 分隔重复字符遵循标准 CTC 规则。
- 只有完整满足语法的候选才能返回。
- 候选还必须通过 `analyzeArithmetic` 且结果不能是 `unsupported`；`non_integer_division` 可以作为识别文本返回，但必须由现有解释器标记为不可填写。
- 解码器不修改 logits、dims 或 charset。

### 回退策略

`DdddOcrEngine` 仍然只预处理和推理一次。

- `digits`、`letters`、`alphanumeric` 继续调用现有 `decodeCtc`。
- `arithmetic` 同时从相同 logits 计算现有贪心结果和语法候选。
- 语法候选存在且 `analyzeArithmetic` 结果不是 `unsupported` 时，返回语法候选。
- 语法候选不存在或无效时，返回现有贪心结果。

第一版不因语法完整就人为提高 confidence。选出完整候选后，对该文本执行一次受约束 CTC Viterbi 对齐；每个发射字符取其对齐区间内最高的完整类别 softmax 概率，再按字符求平均。这与现有贪心解码的 confidence 语义保持一致，保证低证据候选仍可被后续 `0.90` 阈值拦截。

### 生成语料解耦

保留 200 张、四类各 50 张、固定种子和当前字体依赖。生成器改为从独立的确定性序列选择以下变量：

- 答案或运算符。
- 字体家族。
- 字号。
- 对比度档位。
- 干扰线数量。
- 旋转角度。

不得再让这些变量共享同一个 `index % N`。测试必须证明每种算术运算符至少覆盖三种字体、四档对比度和两种干扰线数量。

生成语料 manifest 升级为 schema version 2。解析器只接受 version 2 的新生成语料，真实样本 manifest 保持 version 1，避免无关迁移。

## 基准数据流

实施按以下顺序保留前后对照：

1. 生成解耦后的 version 2 语料。
2. 在修改生产解码前运行当前贪心引擎，将报告保存为本地基线。
3. 实现算术语法解码并运行相同语料。
4. 比较整体、分类、运算符和选择性指标。
5. `benchmark/results/` 继续保持 Git 忽略；摘要写入交接文档。

基准仍使用生产 `DdddOcrEngine`、本地模型、字符表和 ONNX Runtime WASM，不引入网络路径。

## 指标

原有指标和门槛保持不变：

- 普通三类整串准确率至少 90%。
- 算术最终填写值准确率至少 90%。
- 字符准确率。
- 冷启动、warm 中位数和 warm P95。
- 高置信错误率。
- 安装占用口径。

新增报告指标：

- 算术按 `+`、`-`、乘法和除法分组的 source accuracy 与 fill accuracy。
- 普通验证码在 confidence `0.90` 下的选择性准确率和覆盖率。
- 算术验证码在 confidence `0.90` 下的选择性准确率和覆盖率。

选择性指标只用于描述“自动处理多少、其中多少正确”，不替代全量硬门槛。

## 失败处理

- 解码参数、维度、字符表或 logits 非法时，沿用现有严格异常语义，不静默回退。
- 只有“没有完整语法候选”属于正常回退条件。
- prefix beam search 超过固定边界时应通过剪枝保持确定性，不使用超时和随机截断。
- 除零或不支持表达式不得成为语法候选；非整除候选交给现有解释器返回 `non_integer_division`，不自动填写。
- benchmark 未达到 90% 时仍写出报告并返回现有退出码 2；这是阶段性结果，不是 runner 崩溃。

## 测试策略

所有行为变更采用 TDD。

### 单元测试

- 减号次于 blank 时，完整算术候选能够恢复减号。
- 重复数字遵循 CTC blank 分隔规则。
- 不完整、双运算符和无右操作数候选不返回。
- 非整除和除零候选不会成为可填写结果。
- 相同 logits 每次返回相同结果。
- 输入集合和 tensor 不被修改。
- `DdddOcrEngine` 对普通模式保持现有结果。
- 算术候选缺失时回退贪心解码。

### 基准测试

- version 2 生成语料保持字节确定性。
- 运算符与样式变量覆盖不再耦合。
- 报告按运算符计算准确率。
- 选择性指标正确处理零覆盖和阈值边界。
- 原有 90% gate 和退出码不变。

### 完整验证

```text
npm test
npm run typecheck
npm run build
npm run benchmark
git diff --check
```

`npm run benchmark` 在未达门槛时预期返回 2；验证需要同时确认报告成功生成且失败原因是 hard gate。

## 成功标准

第一版完成必须满足：

- 所有生产和基准资源完全本地。
- 普通验证码结果无回归，或任何变化都有明确证据和解释。
- 减法 source accuracy 和 fill accuracy 高于同一 version 2 语料上的贪心基线。
- 新增指标可以稳定复现。
- 90% 硬门槛未被修改。
- 未达到 90% 时，交接文档明确记录差距和下一轮计划。

第一版不承诺除法或大小写问题全部解决。后续优先级由 version 2 分项结果决定：除号专用分类器、大小写判别器、预处理集成或授权真实样本驱动的小模型训练。
