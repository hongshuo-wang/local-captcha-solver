# Ppllocr 浏览器兜底引擎设计

## 背景

当前扩展使用 `ddddocr common_old.onnx` 在浏览器内离线识别，并通过数字、字母、字母数字和算式四种解码模式选择候选。真实验证码 `7*3=?` 暴露出两个问题：CTC 解码可能把末尾符号识别成数字，且普通字母数字候选可能因置信度更高而覆盖算式候选。

调研中最接近需求的现成浏览器扩展 Mieru-OCR 仍使用 ddddocr，实际对该截图输出 `7t3a`，无法解决问题。Ppllocr 2.2 是面向高干扰验证码的 MIT 许可 ONNX 模型，字符集原生包含四则运算符、等号和问号，并返回逐字符位置与置信度，因此作为重点候选验证。

## 目标与非目标

目标：

- 只验证 Ppllocr，不继续横向评估 PaddleOCR 等其他引擎。
- 验证原始 Ppllocr ONNX 模型能否由现有 `onnxruntime-web` WASM 运行。
- 验证真实截图中的 `7*3=?` 能否被识别并计算为 `21`。
- 若验证通过，将 Ppllocr 作为可疑结果的按需兜底引擎；正常结果仍走当前轻量 ddddocr 链路。
- 复用 Ppllocr 的预处理、YOLO 输出解码、NMS 和字符排序算法，不重新设计识别模型。

非目标：

- 不训练新的验证码类型分类器。
- 不量化或重新训练 Ppllocr 模型。
- 不建立大型新基准；仅使用真实问题样本和少量现有固定样本做回归保护。
- 不支持滑块、点选、reCAPTCHA 或 hCaptcha。

## 可行性门槛

按以下顺序验证，并在任一硬门槛失败时停止集成：

1. 模型能在 `onnxruntime-web` 的 WASM 执行提供程序中创建会话并完成一次推理。
2. JavaScript 移植的官方预处理和后处理能输出稳定的逐字符结果，不依赖 Python、OpenCV 或服务端。
3. 真实截图识别结果可解析为 `7*3`（允许保留或省略尾部 `=?`），最终填充值为 `21`。
4. 从现有语料中固定抽取数字、字母和字母数字各 5 张，15 张普通验证码均不得被解析为算式。

四项全部成立即认定 Ppllocr 可行并停止其他模型调研。如果真实问题样本仍失败，或普通样本出现算式误判，则不把 80 MB 模型接入正式扩展，并回到现有解码器修正方案。

## 运行架构

### 1. Ppllocr 引擎边界

新增独立 OCR 引擎模块，输入沿用现有图片字节，输出标准 `OcrResult`：

- 将图片按官方实现等比例缩放并填充到 `512 x 512`。
- 生成 RGB、NCHW、`0..1` 的 Float32 张量。
- 使用现有 offscreen 文档中的 `onnxruntime-web` 会话运行模型。
- 按官方 Ppllocr 2.2 实现解析 YOLO 输出：类别最高分过滤、坐标转换、NMS、坐标还原和从左到右排序。
- 将逐字符置信度聚合为整串置信度，并保留原始字符结果供算式解释器处理。

Ppllocr 代码保持独立，不修改现有 ddddocr 解码器，使模型替换和失败回退边界清晰。

### 2. 按需兜底

默认先运行当前 ddddocr。只有出现以下可疑结果时才加载并运行 Ppllocr：

- 多模式候选之间差距不足，工作流需要用户确认；
- 最高候选为字母数字，但同时存在结构接近的算式候选；
- 当前引擎没有产生有效候选。

Ppllocr 返回有效结果后仍经过现有 `resultInterpreter`、算式安全计算和自动填充策略。若 Ppllocr 失败或结果无效，保留原 ddddocr 候选并进入现有确认流程，不因兜底模型故障丢失结果。

### 3. 资源策略

- 模型只在首次需要兜底时创建会话，随后复用。
- 可行性验证阶段模型仅放在临时目录，不改正式构建资源。
- 正式接入时将模型随扩展打包，固定模型来源、版本、SHA-256 和 MIT 许可说明，并纳入资产完整性测试；安装完成后无需联网下载模型。
- 本次不做模型下载器或 IndexedDB 缓存。80 MB 模型文件随包存在，但推理会话仍只在需要兜底时创建。

## 类型判断与算式处理

不新增独立分类模型。Ppllocr 的识别字符自然形成类型证据：

- 仅数字为数字验证码；
- 仅字母为字母验证码；
- 字母与数字混合为字母数字验证码；
- 包含受支持运算符且满足安全算式语法时为算式验证码。

只有完整、安全、无歧义的算式才计算。禁止 `eval`，继续使用现有 BigInt 算式解释器；除零、非整数除法和不支持的表达式进入确认流程。

## 测试与验收

- 单元测试覆盖张量预处理、YOLO 输出维度检查、置信度过滤、NMS、字符排序和非法输出。
- 使用构造输出验证 `7 * 3 = ?` 能标准化为算式结果 `21`。
- 使用真实截图完成一次原模型推理，记录原始字符、最终值、冷启动和热推理耗时。
- 从现有语料固定抽取数字、字母、字母数字各 5 张做冒烟测试，要求没有普通样本被解析为算式，不扩展为完整模型竞赛。
- 运行相关测试、完整单元测试、类型检查以及 Chrome/Edge 生产构建。

验收标准：Ppllocr 在浏览器 WASM 环境可运行，真实问题样本得到 `21`，失败时能回退到现有确认流程，正常 ddddocr 路径不承担 Ppllocr 的启动成本。
